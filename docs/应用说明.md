## 二、改动 1：修复 `states:` 槽位的 refetch 隐患（P0）

**问题**（原 `_StatesScopeState.didUpdateWidget`）：
```dart
if (old.config != widget.config && widget.config != null) { // ← 引用比较，永远为 true
  _future = null; // 父级每重建一次就重拉一次 Future
  addPostFrameCallback(() => setState(() => _future = _fetch()));
}
```
`AppPageStates` 未重写 `==`，父级 `build` 每次都 `new` 一个新实例 → 引用永不相等 →
**祖先一旦重建（例如包了 `context.watch<XProvider>()`）就重新拉取**，在响应式页面会形成
「重建 → refetch → 重建」循环。这也是 `storage_page.dart` 实际绕过 `states:` 改用手动判断的底层原因。

**修复**：给 `AppPageStates` 增加显式的 `reloadKey`，只按它判断是否重载：
```dart
final Object? reloadKey;   // 新增：改变它才触发重载；为 null 则只在首次挂载加载一次

// didUpdateWidget（修复后）
final nextKey = widget.config.reloadKey;
if (nextKey != null && nextKey != _loadedReloadKey) {
  addPostFrameCallback(() { if (mounted) setState(() => _future = _fetch()); });
}
```
同时移除了原实现里 `widget.config != null` 这个对非空字段的多余判空。

**配套**：文件头新增「使用约定」注释，明确 `states:` 仅用于一次性 Future，Provider 页面走手动三态。

**用法示例**：
```dart
// 筛选条件变化需要重新加载
AppPageStates<List<Item>>(
  reloadKey: _currentFilter,   // 值变了才 refetch
  load: () => repo.list(_currentFilter),
  buildData: (ctx, items) => ItemList(items),
  emptyWhen: (d) => d.isEmpty,
)
```
